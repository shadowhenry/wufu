## 修复：self.ctx.createImage is not a function（图片加载全崩）

### 根因
- 小程序 `canvas type="2d"` 的 **`createImage()` 挂在 canvas 节点上**，2d 上下文（`ctx`）里没有。
- `pages/editor/editor.js` 的 `loadOneImage` 写成了 `self.ctx.createImage()`，真机/模拟器直接抛
  `TypeError: self.ctx.createImage is not a function`，从 `useWallMaterial → addMaterialToLayer → loadOneImage` 整条链崩掉。
- `utils/thumbnail.js` 的 `loadLocalImage` 同样写成 `ctx.createImage()`，因为有 try/catch 静默吞掉，
  表现是模板缩略图永远只有占位块、不出图。

### 修复
- `pages/editor/editor.js` `loadOneImage`：
  - 守卫改为 `if (!path || !self.canvas)`。
  - `self.ctx.createImage()` → `self.canvas.createImage()`。
  - `createImage` 包 try/catch，画布未就绪时静默 resolve，不再让 Promise 链崩。
  - 本地 path 分支也补上 `.catch(() => {})`。
- `utils/thumbnail.js`：`loadLocalImage(canvas, layer, images)` 改用 `canvas.createImage()`，
  `renderThumbnail` 传 canvas 节点进去。
- `tests/thumbnail.test.js`：测试桩的 canvas 补上 `createImage`（原先只在 ctx 上有）。
- `tests/editor-scale.test.js` 新增静态守卫：禁止 `ctx.createImage()`，必须 `canvas.createImage()`。

### 结论
- 全量 **268 passed / 0 failed**，WXML 静态检查全部通过，所有 JS 语法检查通过。

## 修复：图片背景和颜色背景切换「无效」

### 根因
- `utils/poster.js` 的 `drawLayer`：图片缺失时画的占位块是**完全不透明**的 `#efe7d8`，
  没有跟随 `layer.opacity`。底图默认 opacity 只有 0.4，占位块却铺满整幅画布，
  于是换背景色、换底图都被这块不透明占位块挡住 —— 用户看到的就是「切换无效」。
- 之前 `createImage` 归属写错（已在上一节修复）导致**所有图片都加载失败**，
  占位块常驻，这个问题被长期掩盖。
- 另外 `pickBackground` 只改 `this.design.background` 就 `render()`，没有 setData，
  色板不会高亮，用户点了也看不出选中了哪个。

### 修复
- `utils/poster.js` `drawLayer` 的占位块跟随 `layer.opacity`（写入 `ctx.globalAlpha`），
  底图 0.4 时占位块半透明，背景色能透出来。

  - 新增 `currentBgValue()`：把 `background.color` / `background.gradient` 还原成色板 value。
